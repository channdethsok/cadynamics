## 1. Context & Motivation

While high-level training pipelines operate directly on PyTorch `.pt` shards containing multi-view visual tensors `[4, 3, 224, 224]` and topological graphs, researchers, domain engineers, and reviewers require concrete, inspectable CAD artifacts:
1. **Geometric Ground Truth**: The ability to export each intermediate solid state $S_k$ directly as a standard OpenCASCADE `.step` (ISO 10303) and `.stl` mesh file, enabling inspection in CAD packages (FreeCAD, Fusion 360, SolidWorks, MeshLab).
2. **Reversibility & Original Assets**: Maintaining complete fidelity with the raw dataset by packaging the original CadQuery Python script, the original final STEP/STL files, and raw multi-angle PNG renders.
3. **Multi-Modal Visual Timelapses**: Generating 4-view contact sheets across $(S_0 \xrightarrow{A_0} \ldots \xrightarrow{A_{K-1}} S_K)$ and animated 3D isometric GIFs depicting progressive volumetric construction.

## 2. Technical Decisions & Instrumentation

### 2.1 Live In-Memory Solid Retention
We extended [`CadQueryRuntimeTracer`](../../src/data/instrumentation.py) with an optional `retain_solids: bool = False` flag and `get_solids() -> List[Any]` method. At each intercepted solid commit:
```python
if self.retain_solids:
    self.solids.append(result.val())
```
Because CadQuery functional methods return new Workplane compounds rather than mutating existing shapes in-place, each solid in `tracer.solids` represents an immutable geometric snapshot $S_k$ that can be exported independently:
```python
solid.exportStep(str(step_cad_path))  # True B-Rep ISO 10303 STEP
solid.exportStl(str(stl_cad_path))    # Triangulated 3D mesh
```

### 2.2 Hierarchical Debug Directory Architecture
Each debug sample is organized into a dedicated, self-contained directory under `data/debug/`:
```text
data/debug/sample_<idx>_<uuid_prefix>/
├── original/
│   ├── code.py                      # Original executable CadQuery code
│   ├── final_original.step          # Parquet ground-truth final STEP
│   ├── final_original.stl           # Parquet ground-truth final STL
│   ├── metadata.json                # Row metadata (latencies, ops count)
│   └── raw_dataset_renders/         # Original 8 multi-angle dataset renders
├── intermediate_steps/
│   ├── step_00_empty/               # Neutral gray canvas [4, 3, 224, 224]
│   ├── step_01_<op>/                # Solid STEP, STL, 4-view PNGs, action/state JSON
│   └── ...
├── visualizations/
│   ├── evolution_contact_sheet.png  # Synchronized 4-view transition strip
│   └── construction_history_iso.gif # 3D isometric timelapse animation
├── trajectory.pt                    # Extracted PyTorch trajectory dictionary
└── README.md                        # Formatted inspection report and metrics table
```

### 2.3 Early PyVista Mesa Handshake
To prevent software Mesa OpenGL collisions in headless environments, `tests/test_export_debug_samples.py` pre-initializes a minimal off-screen PyVista context prior to importing OpenCASCADE / CadQuery.

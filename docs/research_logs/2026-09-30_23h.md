## 1. Motivation: 1-to-1 Shard Naming & Lineage Architecture

Previously, preprocessed intermediate state trajectories were grouped into generic sequential chunks (`shard_0000.pt`, `shard_0001.pt`). While functionally sufficient for single-machine prototyping, this created operational friction:
1. **Cluster Scalability**: Running multi-node preprocessing jobs on high-performance compute clusters required coordination over shard counter indices to prevent file collisions.
2. **Resumption & Fault Tolerance**: Resuming a job required inspecting internal counts rather than checking file existence.
3. **Lineage Traceability**: Re-associating a processed trajectory back to its original raw CadQuery source code, full final STEP model, or rendered STL required indirect lookup.

### The Solution: 1-to-1 Deterministic Parquet-to-PT Mapping
Each raw parquet file in `data/zero_to_cad_100k/data/<split>/<stem>.parquet` maps **1-to-1** directly to:
```
data/processed_data/<split>/<stem>.pt
```
For example:
- **Raw Parquet**: `data/zero_to_cad_100k/data/val/85_5c8bc6f0459e4abba11cfaec2884d1f8_000000_000000-0.parquet`
- **Processed Shard**: `data/processed_data/val/85_5c8bc6f0459e4abba11cfaec2884d1f8_000000_000000-0.pt`

Within each `.pt` shard:
- `shard["metadata"]["source_shard"] = "<stem>.parquet"`
- For every trajectory record $k$:
  - `record["source_shard"] = "<stem>.parquet"`
  - `record["source_row"] = row_index`
  - `record["part_id"] = uuid`

### Direct Reverse Lookup in $O(1)$ Time
Given any trajectory in a `.pt` file, one can immediately access the original raw CadQuery script, complete STEP CAD geometry, or STL mesh:
```python
import pyarrow.parquet as pq
raw_pq = raw_dataset_dir / traj["source_shard"]
tbl = pq.read_table(str(raw_pq))
raw_record = tbl.slice(traj["source_row"], 1).to_pylist()[0]
step_bytes = raw_record["step_file"]  # Complete OpenCASCADE STEP
cad_code   = raw_record["cadquery_file"]  # Original script
```

## 2. Implementation Changes

1. **`scripts/preprocess_intermediate_states.py`**:
   - Replaced flat-buffered chunking with per-shard file-by-file execution.
   - Added automatic skip-if-exists logic:
     ```python
     target_pt = split_dir / f"{pf_path.stem}.pt"
     if target_pt.exists() and not args.overwrite:
         if target_pt.stat().st_size > 0:
             logger.info(f"Skipping {target_pt.name} (already exists)...")
             continue
     ```
   - Added `--overwrite` flag to allow intentional regeneration when desired.
   - Added `--max-shards` argument for fine-grained batch scheduling.
   - Maintained persistent worker pool across shards for low process-spawn overhead.

   - Updated shard discovery to dynamically scan `data/processed_data/**/*.pt` using glob rather than hardcoding static paths.

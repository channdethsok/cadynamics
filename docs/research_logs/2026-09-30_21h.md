## 1. Context & Motivation

In our earlier iterations, intermediate CAD states were represented primarily through 2D surface patches (`brep_nodes` and `brep_uv`) along with face-adjacency topology (`brep_edge_index`). However, CAD boundary representations (B-Rep) are inherently hierarchical cell complexes consisting of **faces (2D)** bounded by **edges/curves (1D)** bounded by **vertices (0D)**.

Predictive world modeling for parametric CAD operations (such as `fillet`, `chamfer`, and boolean trimming) requires explicit 1D curve geometry and edge convexity, since operations like fillets and chamfers directly operate on and modify edges.

Furthermore, state naming consistency required transitioning from singular/ad-hoc prefixes (`brep_nodes`, `brep_uv`, `brep_edge_index`) to systematic plural keys (`faces_features`, `faces_uv`, `edges_features`, `edges_u`, `faces_adjacency_index`) to match the structural plurality of geometric entities.

Finally, 2D sketch profiles (Path A) require canonical representation in the local 2D workplane coordinate space $(u, v)$ rather than raw 3D world space, ensuring orientation invariance.

## 2. Technical Decisions & Schema 0.2.0 Specifications

### 2.1 Plural State Geometry Keys
All intermediate states $S_k$ now enforce explicit plural naming:
- `faces_features`: `FloatTensor[N_faces, 32]` (one-hot surface classification, geometric invariants, area, inertia, bounding box).
- `faces_uv`: `FloatTensor[N_faces, 7, 16, 16]` (regular $16 \times 16$ UV grid: $[x, y, z, n_x, n_y, n_z, \text{mask}]$).
- `edges_features`: `FloatTensor[N_edges, 16]` (one-hot curve classification, length, midpoint, unit tangent, flags).
- `edges_u`: `FloatTensor[N_edges, 6, 16]` ($16$ equidistant parameter samples: $[x, y, z, t_x, t_y, t_z]$).
- `faces_adjacency_index`: `LongTensor[2, E_adj]` (bidirectional face-to-face adjacency across shared topological edges).

### 2.2 16-Dimensional Edge Feature Representation
Each edge $e \in E$ is characterized by an explicit 16-dimensional vector:
1. `is_line` (one-hot): Linear segment (`GeomAbs_Line`).
2. `is_circle` (one-hot): Circular arc or complete circle (`GeomAbs_Circle`).
3. `is_ellipse` (one-hot): Elliptical curve (`GeomAbs_Ellipse`).
4. `is_parabola_hyperbola` (one-hot): Conic section (`GeomAbs_Parabola` / `GeomAbs_Hyperbola`).
5. `is_bspline_bezier` (one-hot): Freeform curve (`GeomAbs_BSplineCurve` / `GeomAbs_BezierCurve`).
6. `is_other_curve` (one-hot): Analytical offset or other curves (`GeomAbs_OtherCurve`).
7. `length`: Metric arc length scaled via SymLog ($\operatorname{symlog}(L) = \operatorname{sign}(L) \ln(1 + |L|)$).
8. `midpoint_x`: Midpoint $X$ normalized via $\tanh(x / 100.0)$.
9. `midpoint_y`: Midpoint $Y$ normalized via $\tanh(y / 100.0)$.
10. `midpoint_z`: Midpoint $Z$ normalized via $\tanh(z / 100.0)$.
11. `tangent_x`: Midpoint unit tangent $T_x$.
12. `tangent_y`: Midpoint unit tangent $T_y$.
13. `tangent_z`: Midpoint unit tangent $T_z$.
14. `is_closed`: Binary flag (1.0 if closed loop, 0.0 otherwise).
15. `is_degenerated`: Binary flag (1.0 if degenerated to a singular point, e.g. cone apex).
16. `convexity`: Dihedral angle convexity between adjacent faces at midpoint ($+1.0$ convex, $-1.0$ concave, $0.0$ smooth/laminar).

### 2.3 1D Curve Parameter Sampling (`edges_u`)
For each edge, the underlying 3D parametric curve $C(u)$ is sampled across 16 uniform parameter intervals $u_i \in [u_{\min}, u_{\max}]$. At each point, we extract 3D coordinates and unit tangent vectors:
$$\mathbf{P}(u_i) = (x, y, z), \quad \mathbf{T}(u_i) = \frac{C'(u_i)}{\|C'(u_i)\|}$$
yielding an exact shape of `[N_edges, 6, 16]`.

### 2.4 Path A: Canonical 2D Workplane Profile Representation
For sketch-based extrusion and cut operations, the 2D cross-section wire is discretized into 64 sampled points projected into the local coordinate system of the active workplane:
$$\mathbf{p}_{\text{local}} = \mathbf{R}_{\text{plane}}^T (\mathbf{p}_{\text{world}} - \mathbf{o}_{\text{plane}})$$
resulting in:
- `points_2d`: `FloatTensor[64, 2]`
- `plane_origin`: `FloatTensor[3]`
- `plane_normal`: `FloatTensor[3]`
- `plane_xdir`: `FloatTensor[3]`

This representation guarantees canonical 2D planar profile invariance regardless of where the workplane is located or oriented in 3D space.

### 2.5 4-View Canonical Multi-View Visual Representation (`images: FloatTensor[4, 3, 224, 224]`)
To eliminate 3D geometric self-occlusion (grounded in Autodesk's *Zero-to-CAD* and *CAD-MLLM*), intermediate states represent visual appearance via 4 synchronized canonical camera perspectives:
1. `ISO`: 3D isometric overview providing global aspect and depth cues.
2. `FRONT`: Projection onto the $XZ$ plane (looking along $-Y$, $Z$ up).
3. `TOP`: Orthographic projection onto the $XY$ plane (looking down $-Z$, $Y$ up).
4. `RIGHT`: Projection onto the $YZ$ plane (looking along $-X$, $Z$ up).

Rendering enhancements:
- **SSAA Anti-Aliasing**: Sub-pixel smoothing eliminating stair-stepping artifacts on curved/diagonal CAD boundaries.
- **Studio 3-Point Lighting Kit**: Directional key, fill, and ambient lighting separating perpendicular faces tonally.
- **Parametric Feature Edges**: High-contrast dark charcoal outlines (`#1A1A1A`, width 1.5) highlighting B-Rep boundaries.
- **Tight Bounding-Box Zoom**: $1.2\times$ framing ensuring the CAD solid occupies $\sim 80\%$ of the canvas.

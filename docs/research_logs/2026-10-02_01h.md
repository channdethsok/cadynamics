## 1. Context & Motivation

As the CADynamics project transitions from Phase 1 data extraction and dataset serialization into Phase 2 model prototyping and training, experiment management becomes critical. 

In parametric 3D CAD research, models must ingest heterogeneous, high-dimensional multi-modal inputs:
* Disjoint union Face-Adjacency Graphs (FAG) with UV curve/surface samples.
* Multi-view canonical rendered isometric/orthographic projections.
* Action tokens, continuous SymLog tool parameters, and reference entities.

Hardcoding hyperparameter dimensions, batch sizes, learning rates, or dataset paths directly in code creates severe technical debt, inhibits reproducibility, and complicates hyperparameter sweeps across cluster environments.

To establish industry-standard research hygiene (standard across DeepMind, FAIR, and top ML labs), we integrated **Hydra** (`hydra-core`) with hierarchical configuration composition.

## 3. Configuration Architecture & Composition

We established a modular `configs/` structure separating concerns into distinct groups (`data`, `model`, `trainer`):

```text
cadynamics/
├── configs/
│   ├── config.yaml              # Root entrypoint & default composition
│   ├── data/
│   │   ├── zero_to_cad.yaml     # Production Zero-to-CAD-100K dataset settings
│   │   └── debug.yaml           # Low-overhead 10-sample dry-run settings
│   ├── model/
│   │   ├── dummy.yaml           # Pipeline validation baseline (Linear MLP)
│   │   └── brep_encoder.yaml    # B-Rep GNN / Transformer architecture specification
│   └── trainer/
│       └── default.yaml         # Optimization, precision, device, and schedule
```

### 3.1 Root Configuration (`configs/config.yaml`)
Defines default composition groups and automated timestamped output directories:
```yaml
# @package _global_
defaults:
  - data: zero_to_cad
  - model: dummy
  - trainer: default
  - _self_

seed: 42
exp_name: "cadynamics_dev"

hydra:
  run:
    dir: outputs/${now:%Y-%m-%d}/${now:%H-%M-%S}
  sweep:
    dir: multirun/${now:%Y-%m-%d}/${now:%H-%M-%S}
    subdir: ${hydra.job.num}
```

### 3.2 Decoupling Exploratory Models via Dummy Baselines
A recurring bottleneck in AI research is waiting for a complex model architecture to be fully implemented before validating data ingestion, batching, and loss computations.

To solve this:
1. **`configs/model/dummy.yaml`**: Provides a lightweight MLP baseline that matches tensor input/output shapes. This allows immediate testing of DataLoader collators, GPU allocation, and training loop mechanics.
2. **`configs/model/brep_encoder.yaml`**: Formulates the hyperparameter specification for the upcoming B-Rep Graph / Transformer encoder (face features, edge dimensions, attention heads, layers, dropout) without requiring immediate implementation:
   ```yaml
   name: "brep_encoder"
   face_feature_dim: 128
   edge_feature_dim: 64
   hidden_dim: 256
   num_heads: 8
   num_layers: 6
   dropout: 0.1
   activation: "gelu"
   pooling: "mean"
   ```

## 4. Runner Implementation (`scripts/train.py`)

A unified entrypoint script was implemented using `@hydra.main`:
* Logs the fully resolved configuration hierarchy.
* Enforces deterministic seed initialization (`torch.manual_seed`).
* Dispatches model instantiation based on `cfg.model.name`.
* Emits informative warnings when an experimental placeholder model is selected without blocking script execution.

---

## 5. Verification & Validation Runs

We conducted end-to-end smoke tests to confirm parameter resolution and dynamic CLI overrides:

### Run 1: Default Execution
```bash
uv run python scripts/train.py
```
**Outcome**: Resolved `zero_to_cad` data config, `dummy` model architecture, and `default` trainer settings. Built and verified the baseline PyTorch model `Sequential(Linear, ReLU, Linear)` in under 1 second.

### Run 2: Dynamic CLI Override (Debug Data + B-Rep Spec + Custom LR)
```bash
uv run python scripts/train.py data=debug model=brep_encoder trainer.lr=5e-5
```
**Outcome**:
* Successfully swapped data loader config to `batch_size: 2`, `num_workers: 0`, `max_samples: 10`.
* Overrode `trainer.lr` to `5.0e-5`.
* Loaded `brep_encoder` hyperparameters (`hidden_dim: 256`, `num_layers: 6`).
* Caught placeholder architecture cleanly with structured logging.

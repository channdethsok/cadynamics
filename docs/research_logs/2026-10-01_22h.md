## 2. Current System Status & Verified Capabilities

The repository currently provides a robust, mathematically grounded, and empirically tested offline extraction and data-loading infrastructure:

* **Zero Proxy Approximations**: Every intermediate state $S_k$ is derived directly from an executed in-memory OpenCASCADE/CadQuery solid compound immediately following operation $A_{k-1}$, preserving strict causal lineage:
  $$\tau = (S_0, A_0, S_1, A_1, \ldots, A_{K-1}, S_K)$$
* **Dual-Domain State Representation (Schema 0.3.0)**:
  * **Visual**: 4 canonical camera views (`iso`, `front`, `top`, `right`) rendered off-screen at $224 \times 224$ uint8 using PyVista/VTK with clean CAD feature edge extraction.
  * **Topological / B-Rep**: 32-dim analytical face features, $[N_f, 7, 16, 16]$ trimmed UV surface grids, 16-dim edge features, $[N_e, 6, 16]$ 1D curve samples, and Face-Adjacency Graph (FAG) `faces_adjacency_index` $[2, E_{adj}]$.
* **Action Representation**:
  * 15 canonical CAD commands (`CANONICAL_COMMANDS`), 5 reference entity types (`REF_NONE`, `REF_WORKPLANE`, `REF_FACE`, `REF_EDGE`, `REF_VERTEX`), SymLog continuous parameter scaling, and 64-point local workplane sketch profile sampling.
* **Production Sharding & Bidirectional Lineage**:
  * 1-to-1 deterministic Parquet-to-PT sharding with $O(1)$ reverse lookup to raw CadQuery code, STEP solids, and STL meshes.
  * Fault-tolerant multiprocessing with 15-second per-part timeout protection (97–99% parsing success rate on Zero-to-CAD 100K).
* **PyTorch DataLoader**:
  * Disjoint union batching for variable-sized face/edge graphs (`batch_faces`, `batch_edges`) and stacked multi-view image tensors.
* **Inspection & Debug Tooling**:
  * Automated export of intermediate STEP, STL, 4-view contact sheets, and animated isometric GIFs.

## 3. Literature Synthesis & Phase 1 Reconsiderations

Recent advancements in B-Rep representation learning and CAD foundation models (2021–2025) highlight several areas where Phase 1 representations can be strengthened:

### 3.1 B-Rep Topology: UV-Net Style (FAG + Edge Attributes) vs. BrepNet Style (Bipartite Complex)

A foundational architectural question in CAD representation learning is:
> *“When constructing the B-Rep graph, is a node a face and an edge of the graph a physical CAD edge?”*

#### The Theoretical Formulation: Face-Adjacency Graph (FAG)
In standard CAD geometric deep learning (grounded in **UV-Net**, Jayaraman et al., CVPR 2021):
* **Graph Nodes**: The **faces** of the 3D solid ($N_{\text{faces}}$).
* **Graph Edges**: The **physical boundary edges** separating adjacent faces.
* Because message-passing graph neural networks operate on **directed** edges, each physical edge shared between two faces $A$ and $B$ corresponds to **two directed graph edges**:
  $$e_{A \to B} = (A, B) \quad \text{and} \quad e_{B \to A} = (B, A)$$
  Hence, for a closed 2-manifold solid, the number of directed graph edges is $E_{\text{adj}} = 2 \times N_{\text{edges}}$.

```
Paradigm A: UV-Net Style (Homogeneous FAG with Directed Edge Attributes)
                  [ Face A Node ] (feat: 32-D)
                       │    ▲
         (e_{A -> B})  │    │  (e_{B -> A})
         edge_attr:    │    │  edge_attr:
         feat(Edge k)  ▼    │  feat(Edge k)
                  [ Face B Node ] (feat: 32-D)
```

```
Paradigm B: BrepNet Style (Bipartite Heterogeneous Cell Complex)
     [ Face A Node ]               [ Face B Node ]
     (feat: 32-D)                  (feat: 32-D)
            │                             ▲
            └───► [ Edge k Node ] ────────┘
                  (feat: 16-D)
```

#### The Gap in Our Current Implementation
While our conceptual model targeted the UV-Net formulation, the actual tensor shapes in Schema 0.3.0 suffered from an indexing disconnect:
1. `faces_features` has shape `[N_faces, 32]`.
2. `faces_adjacency_index` has shape `[2, E_adj]` (containing directed pairs $(u, v)$).
3. `edges_features` has shape `[N_edges, 16]` (one per physical CAD edge).
4. **The Mismatch**: Because $N_{\text{edges}} \neq E_{\text{adj}}$, `edges_features` cannot be directly passed as `edge_attr` in standard PyG `Data(x, edge_index, edge_attr)`. Furthermore, in `occ_extractor.py:254-275`, when `faces_adjacency_index` was populated, the index of the physical edge was **discarded**! As a result, the directed edge $(A \to B)$ had no pointer back to physical Edge $k$.

#### Resolution Path for UV-Net Style in Phase 1
To fully realize the UV-Net architecture already prototyped in [`src/models/brep_encoder.py`](../../src/models/brep_encoder.py) (`UVNetGraphEncoder`, `_NodeConv`, `_EdgeConv`, `Fuse`):
1. **Preserve Edge Mapping in `occ_extractor.py`**:
   During OpenCASCADE shape traversal via `edge_to_faces`:
   * For each physical CAD edge $k \in [0, N_{\text{edges}}-1]$ bounding faces $(f_1, f_2)$:
     * Add $(f_1, f_2)$ with attribute vector $\mathbf{e}_k \in \mathbb{R}^{16}$.
     * Add $(f_2, f_1)$ with attribute vector $\mathbf{e}_k \in \mathbb{R}^{16}$.
2. **Output Aligned `edges_features_directed`**:
   Output tensor `edge_attr` with shape `[E_adj, 16]`, exactly matching `faces_adjacency_index [2, E_adj]`.
3. **Precompute `reverse_edge_indices`**:
   Precompute a mapping tensor `reverse_edge_indices: LongTensor[E_adj]` where entry $i$ points to the index of the reverse edge $(v \to u)$. This enables UV-Net's edge fusion layer:
   $$\mathbf{e}_{\text{combined}} = \mathbf{e}_{uv} + \mathbf{e}_{vu} = \text{efeats} + \text{efeats}[\text{reverse\_edge\_indices}]$$
   in pure $O(1)$ tensor indexing without runtime dictionary lookups.

#### Comparison: UV-Net vs. BrepNet Trade-offs
* **UV-Net FAG Style**:
  * *Pros*: Directly matches our existing encoder in `brep_encoder.py`; standard homogeneous GNN layers; highly optimized sparse matrix operations.
  * *Cons*: Edge features are replicated across forward/backward directed edges.
* **BrepNet Bipartite Style**:
  * *Pros*: Faces and Edges are both first-class nodes; ideal for action selection masks when filleting/chamfering edges.
  * *Cons*: Requires heterogeneous graph message passing (`Face -> Edge` and `Edge -> Face` alternating convs).
* **Recommendation**: Implement **UV-Net style aligned edge attributes** as the immediate primary graph format, while maintaining the physical edge list `[N_edges, 16]` for edge-selection action masks.

### 3.2 Action Space: Sketch Analytic Primitives vs. 64-Point Sampling
* **Current Limitation**: 2D sketch cross-sections are discretized into 64 sampled points projected into local workplane coordinates $[64, 2]$.
* **Literature Grounding**: In *SkexGen* (Frankenberger et al.), *DeepCAD* (Wu et al.), and *CAD-MLLM* (Autodesk 2024), sketch loops are defined by analytical geometric primitives: lines, arcs, circles, and spline segments with explicit parameters (endpoints, centers, radii). Discretized point clouds lose sharp corners, tangencies, and loop constraints.
* **Actionable Modification**: Retain the 64-point sampled profile as a spatial conditioning signal, but augment the action schema with structured analytic sketch primitive tokens extracted directly from CadQuery's `ctx.pendingWires`.

### 3.3 Collation Gap: Entity Selection Grounding
* **Current Limitation**: While `action_extractor.py` records matched face/edge indices in $S_k$ using OpenCASCADE `IsSame` identity, `dataset.py:collate_transition_batch` omits `ref_entity_indices` because the number of selected entities $M$ varies per operation.
* **Problem**: The future world model cannot determine *which* face or edge of the current geometry is being modified.
* **Actionable Modification**: Expose boolean node selection masks in the collated batch:
  * `selected_faces_mask`: `BoolTensor[Total_faces]`
  * `selected_edges_mask`: `BoolTensor[Total_edges]`

### 3.4 Visual Domain: Scale Jumps from Dynamic Framing
* **Current Limitation**: Offscreen rendering dynamically zooms ($0.85\times$) onto the current solid's local bounding box at each step. Small feature additions (or additions of large thin structures) cause abrupt visual scale jumps between $S_k$ and $S_{k+1}$.
* **Actionable Modification**: Store the metric bounding box dimensions and scale delta $(\Delta \mathbf{bbox}_t)$ alongside the image tensor, or maintain fixed-margin camera framing grounded to the bounding volume.

### 3.5 Trajectory Modeling: Multi-Step Horizons
* **Current Limitation**: `CADTransitionDataset` samples only single-step transitions $(S_t, A_t, S_{t+1})$.
* **Actionable Modification**: Support horizon parameter `rollout_length: int = H`, enabling extraction of multi-step trajectories $(S_t, [A_t, \dots, A_{t+H-1}], S_{t+H})$ for multi-step predictive loss formulations.
